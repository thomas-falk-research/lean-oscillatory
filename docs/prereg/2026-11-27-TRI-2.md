# Pre-registration: second numeric test of batch TRI (resolution of the first run's failures)

Registered 2026-11-27 (session 15), after the first registered test (`docs/prereg/2026-11-27-TRI.md`) was run and
before the program below has been run. The first run's output is kept unchanged
(`numerics/results-tri-checks-2026-11-27.txt`, OVERALL: FAIL).

**What was known at registration: everything from the first run and from the lead's diagnosis.** The diagnosis used
the first program's own functions, loaded after a hash check; its script is in the lead's scratch.
- **a = 0.05:** the four solutions have `q₄` within 2.0e−12 of the predicted values at step 1e−3, just over the
  tolerance 1e−12, and within 3.1e−14 at step 5e−4.
- **a = 0.5:** the anti-diagonal point `(π, π)` (θ = π) is not among the solutions. There all third derivatives
  vanish, so it is a degenerate root of the search system, and Newton's method did not converge within mpmath's
  default number of steps.
- **a = ±a*:** the A5 point is a degenerate root of the same kind. Newton's method fails within the default steps
  and converges with 400 steps (residual about 3e−36). At the exact point, `q₄ = −1.3e−18` and
  `q₆ = −0.0147313912743`, against the target `−0.0147313912747`.

So this registration is not an independent test. It decides whether the first run's failures were all ones of
resolution, as the lead infers.

## Protocol (fixed now)

Everything is exactly as in the first registration: the values of a, the criteria T1 (i) to (iv), T2, K1 and K2 with
the same tolerances, and the functions that compute them. The second program loads the first and refuses to run
unless its SHA-256 is the registered 1446a8d4dea8675a6e582114bd1b02f00db754c85d3c0629062441df5a402d81. Two changes:

1. Newton's method in the search is allowed 400 steps (`maxsteps=400`, `verify=False`). A solution is accepted only
   if both equations are below 1e−30, as before.
2. The reduced coefficients are read off with interpolation step 5e−4 in place of 1e−3.

Overall PASS iff every line is PASS.

**Outcomes and what follows, fixed now.**
- PASS: the first run's failures were of resolution, and the statements of batch TRI are written.
- A FAIL of T1 (i) or (ii) is a counterexample to K1 or K3 and stops the batch.
- Any other FAIL is a defect, to be explained before any statement.
