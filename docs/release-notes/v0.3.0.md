# OscInt v0.3.0 — release notes

The first release with a stable surface for downstream projects (`docs/policy.md`): the entry point
`import OscInt.API`, the machine-readable statement list `stamps/statements.json`, the downstream checker
`tools/oscint_check.py`, and the first Mathlib-idiom front ends (front-end batches 1 and 2). Toolchain
`leanprover/lean4:v4.35.0`, Mathlib `56a005855ea17e0b0958f73ec801ae140b0a1679`.

The release commit's full hash is in `docs/release-notes/v0.3.0.commit` (written in the commit after it, so it is not
in the tagged tree). CI job `release-pin` (`tools/check_release_pin.sh`) requires the tag `v0.3.0` to point to exactly
that commit and recomputes both hashes there. Downstream projects:

```toml
[[require]]
name = "oscint"
git = "https://github.com/thomas-falk-research/lean-oscillatory"
rev = "v0.3.0"
```

```bash
lake build OscInt Blueprint   # the check replays every OscInt and Blueprint module, not only those you import
python3 .lake/packages/oscint/tools/oscint_check.py --statement <statement> \
  --expect-sha256 32eac265a3468d5e5e02526df8bc37db1412c339f5fec62fee166c08490e24c0
```

Against tampering (README), keep your own copy of `tools/oscint_check.py` whose SHA-256 equals the one above, and
pin the full commit hash from `docs/release-notes/v0.3.0.commit` instead of the tag name.

## Statement changes

None to an existing statement (CHANGELOG "v0.3.0", "Statement changes"): the eleven statements of v0.2.0 keep their
files and commitments. Added: F1, F2 (front-end batch 1) and fourteen front-end batch-2 statements (C1–C9, C7′,
FE-S2.1, FE-S2.2, FE-S3, FE-S4.1′). Newly proved: S4.4, F1, F2 and the fourteen. Twenty-seven statements in all, each
with a row in `docs/STATUS.md`.

## Publishing (owner)

1. On GitHub: Releases → Draft a new release → Choose a tag → type `v0.3.0` → Target: the commit whose full hash is
   in `docs/release-notes/v0.3.0.commit` (it is the parent of the commit that adds that file) → title
   `OscInt v0.3.0` → paste this file from "The first release…" to the end of "Evidence" → Publish release.
2. Zenodo mints the version DOI. Add it to `CITATION.cff` (`identifiers:`, "Version 0.3.0") and to README's citation
   line in a follow-up commit.
3. Re-run CI job `release-pin` (Actions tab → latest `ci` run → Re-run jobs), or push any commit: it turns green, and
   `consumer-release` builds a project that requires OscInt by this tag.
