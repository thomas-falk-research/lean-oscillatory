## Adversarial referee
S4.4 and its trust chain: no findings. The dependency surface:
- **B1 (BLOCKER), accepted.** `oscint_check.py` now (a) requires each statement constant to be declared in the module
  of its frozen file (`Environment.getModuleIdxFor?`), and (b) recomputes the commitments by default (`--commitments`
  is gone; `--no-commitments`/`--fast` make the verdict PARTIAL, never PASS). A redefined statement in another module
  fails (a); one in the right module but from a swapped or stale `.olean` fails the commitment or the kernel replay.
  Negative controls: "statement from another module", "changed commitment".
- **M1 (MAJOR), accepted.** The checker replays with `leanchecker`, by default, every OscInt and Blueprint module and
  every module in the transitive dependency closure of each checked theorem, and fails if a constant of that closure
  is declared in the package's root module `OscInt` (which may only import; it is never replayed whole, lessons 14).
  A first fix replayed only the package's module files; re-run against the referee's own reproduction
  (`/tmp/adv6/B/`, the fake theorem in the root module) it still reported PARTIAL with no problem, because the root
  module was not replayed (lessons 18: my control put the theorem in a separate module, so it did not exercise the
  referee's path). After the closure-based fix the reproduction fails ("kernel replay rejected module OscInt: declares
  OscInt.d4Limit …"), and the control "kernel-unchecked theorem" (`examples/consumer/ConsumerKernelControl.lean`, not
  among the package's files, reached only through the closure) fails the replay. The referee's B1 reproduction
  (`/tmp/adv6/A/`) fails the module check, and the kernel replay.
- **M2 (MAJOR), accepted.** The project's `lean-toolchain` and Mathlib `rev` must equal those in `statements.json`.
  Negative controls "other toolchain", "other Mathlib".

  detects drift, not tampering, and tell a consumer to keep their own copy of the checker and pin the hash of
