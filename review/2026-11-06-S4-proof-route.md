## Per-part analysis

**D1 `NormalizeFacts`: TRUE. Size about 50–80 lines.**
- `φ` is differentiable everywhere, so `fderiv (normalize φ) y = fderiv φ y - fderiv φ 0` at every `y`.
- `fderiv_sub_const` holds with no side condition. It gives `dd (normalize φ) = dd φ` as functions; `ddd (normalize φ) = ddd φ` then follows by rewriting.
- The integral identity holds pointwise because `fderiv φ 0 κ = κ.1·∂₁φ(0) + κ.2·∂₂φ(0)`. So `tφ + lin y = tφ(0) + (t·normalize φ + lin (y + t•grad0 φ))`.
- `integral_const_mul` needs no integrability, and `‖exp(i t φ(0))‖ = 1`. The equality therefore holds for every `A`, including non-integrable ones.

**D2 `RescaleFamilyFacts`: TRUE with `C⁴`, over all of `ε ∈ ℝ` (including `ε < 0` and `ε = 0`). Size about 300–700 lines; the largest part.**
- For `ε ≠ 0`: `D^jΨ_ε(z) = ε^{j-3}·D^jφ(εz)`. This uses `ContinuousLinearMap.iteratedFDeriv_comp_right`, `iteratedFDeriv_const_smul_apply` and `compContinuousLinearMap (fun _ => ε•id) = ε^j • _`. The formula is continuous wherever `ε ≠ 0`, whatever the sign of `ε`.
- At `ε = 0`, the limits are those listed in `proof-S4.md`. They need `φ(0) = 0`, `Dφ(0) = 0`, `D²φ(0) = 0`. They also need `D⁴φ` continuous, i.e. bounded near 0, for the `j = 4` term `ε·D⁴φ(εz) → 0`. So `C⁴` is exactly the regularity required: `FamilyCk 4` asks for continuity at `j = 4`.
- Main obstacles:
  - Translating `dd φ 0 = 0` and `cubicCoeffs` (nested `fderiv`) into `iteratedFDeriv`.
  - Symmetry of `D³φ(0)`, which is needed to identify it with `D³` of `cubicPoly (cubicCoeffs φ)`. Mathlib only has second-order symmetry (`ContDiffAt.isSymmSndFDerivAt`); there is no lemma for third-order symmetry of `iteratedFDeriv`.

**D3 `CubicGaugeFacts`: TRUE, and `disc ≠ 0` is the only hypothesis it needs. Size about 150–400 lines.**
- `T[v³] = 6·C(v)`, `H(z) = T[z,·,·]`, and `Hv₁ = (0, ps−r²)`, `Hv₂ = (ps−r², 0)`.
- If `H(z) = 0`, then `C` is the cube of a linear form, so `disc = 0`. If `H ≠ 0` and `v₁ = 0`, then `v₂ = (s, 0)` is nonzero, so some `vᵢ` spans the kernel.
- The case `u ∥ z` gives `∇C(z) = 0` at `z ≠ 0`, a repeated root (by Euler's identity). The other case makes `C` a cube.
- The argument works over ℂ, so by the Nullstellensatz there are certificates putting `disc^k·zᵢ^N` in the ideal generated by `hessDet`, `T[v₁³]`, `T[v₂³]` (and by `p, r, s` for the `hessNorm` part).
- In Lean, `dd`/`ddd` of `cubicPoly` are computed explicitly, as in the `sanity_*` lemmas, and the rest is algebra.

**D4 `GaugeFoldFacts`: TRUE; `C³` is enough (`C²` would do). Size about 120–250 lines.**
- Linearity of `dd` in `v` uses `fderiv_clm_apply` and needs `fderiv Ψ` differentiable at `k` (`C²`).
- Symmetry `dd v w = dd w v` uses `ContDiffAt.isSymmSndFDerivAt` (`C²`). It is needed because `hessDet` uses only `dd (1,0) (0,1)`, while the kernel condition in `FoldOrNondeg` puts `v` in the first slot.
- Homogeneity `ddd (λv)(λv)(λv) = λ³·ddd v v v`: the function `y ↦ dd Ψ y (λv)(λv)` equals `λ²·dd Ψ y v v` at every `y` (`C²` everywhere), and the `w` slot is linear for free.
- `vᵢ ≠ 0` holds automatically: `ddd Ψ k 0 0 0 = (CLM) 0 = 0`, so `T[vᵢ³] ≠ 0` forces `vᵢ ≠ 0`.
- Any kernel vector equals `λ·vᵢ` with `λ ≠ 0`: write `λ` explicitly, e.g. `((-r)x + p y)/(r² + p²)`, and use `field_simp`/`nlinarith`.

**D5 `GaugeOpenFacts`: TRUE; `FamilyCk 3` is enough, and `Λ` may be any topological space. Size about 120–200 lines, plus the bridge described under MINOR 3.**
- For `C³`, `dd Ψ k v w = iteratedFDeriv ℝ 2 Ψ k ![w, v]` (`fderiv_clm_apply`, `iteratedFDeriv_two_apply`). Likewise `ddd Ψ k u v w = iteratedFDeriv ℝ 3 Ψ k ![w, v, u]` (`iteratedFDeriv_succ_apply_left`, with differentiability of `iteratedFDeriv 2` from `C³`).
- The gauge evaluates `D³` at the varying vectors `kerVecᵢ`, so the proof uses joint continuity of evaluation (`ContinuousMultilinearMap.continuous_eval`).
- The tube lemma is `IsCompact.eventually_forall_of_forall_eventually`.

**D6 `GradBoundFacts`: TRUE. Size about 50–80 lines.**
- `Λ × K` is compact, `fderiv` is continuous through `iteratedFDeriv_one_apply`, and so `|∂ᵢΨ_σ| ≤ B`.
- With the max norm, `‖p‖ ≥ G = B + 1` gives some `|pᵢ| ≥ G`, so `|∂ᵢΨ + pᵢ| ≥ 1`.
- Empty `Λ` or empty `K` cause no trouble.

**D7 `CutoffFacts`: TRUE. Size about 30–50 lines.**
- Take a `ContDiffBump (0 : ℝ × ℝ)` with `rIn = 1`, `rOut = 2`. Mathlib provides `HasContDiffBump` for finite-dimensional spaces, and `sanity_ampBound_exists` already uses one.
- `tsupport_eq` gives `closedBall 0 2`; values lie in `[0, 1]`.
- `χ(2z) ≤ χ(z)` needs no monotonicity: if `‖z‖ ≤ 1` then `χ z = 1 ≥ χ(2z)`; otherwise `‖2z‖ > 2`, so `χ(2z) = 0`.

**D8 `TrivialBoundFacts`: TRUE, even though `Q` need not be measurable. Size about 40–70 lines.**
- `M ≥ 0` follows from `‖A k‖ ≤ M` at any point. If `r < 0`, then `A = 0`.
- `norm_integral_le_of_norm_le` with `g = M·indicator(closedBall 0 r)` places no condition on `f`; if `f` is not integrable, its integral is 0 anyway.
- The volume is `(2r)²`, via `closedBall_prod_same`, `Measure.prod_prod` and `Real.volume_closedBall`.

**D9 `DyadicSumFacts`: TRUE. Size about 100–180 lines.**
- Take `J := Nat.find` (least `j` with `t ε_j³ < 1`).
- Then `ε_J² < t^{-2/3}`.
- The sum equals `t^{-5/6}·Σ ε_j^{-1/2}`, which is at most `t^{-5/6}·ε_{J-1}^{-1/2}·√2/(√2−1)`, which is at most `3.414·t^{-2/3}` because `ε_{J-1} ≥ t^{-1/3}`. When `J = 0` the sum is empty.
- The main work is `rpow` bookkeeping and a geometric sum in `√2`.

## Findings

**BLOCKER:** none.

**MAJOR:** none.

**MINOR 1 (D2 route).** `proof-S4.md` Step 2 relies on "symmetry of D³ψ(0) identifies the trilinear form with the polynomial C" and on integral Taylor formulas for each `j`. Mathlib has no third-order symmetry lemma, so it must be derived by applying `isSymmSndFDerivAt` twice: once to `φ` at every point, once to `fderiv φ`. The integral Taylor formulas for `iteratedFDeriv`-valued maps are also expensive. A cheaper route:
- Write `φ = C + R` with `C = cubicPoly (cubicCoeffs φ)`.
- Homogeneity gives `Ψ_ε = C + ε⁻³R(ε·)` by pure algebra.
- Then `D^jΨ_ε(z) = D^jC(z) + ε^{j-3}D^jR(εz)`. Continuity of `D^jC` comes free from `ContDiff`; there is no need to compute `D⁴C = 0`.
- Iterating `Convex.norm_image_sub_le_of_norm_fderiv_le` with `norm_fderiv_iteratedFDeriv` gives `‖D^jR(x)‖ ≤ S‖x‖^{4-j}`, where `S` bounds `‖D⁴R‖` on a ball. So the remainder term is at most `S|ε|‖z‖^{4-j} → 0`.
- The only explicit computation left is `D^iC(0) = D^iφ(0)` for `i ≤ 3`.

**MINOR 2 (D3 tooling).** The route offers "polynomial certificates (Disc · z₁^N … in the ideal)". The machine has no `sympy` (checked), and `polyrith` needs network access. An agent will either need an offline CAS or should formalise the case argument instead. A case split on the rank of `H(z)` and on `z.1 ≠ 0` versus `z.2 ≠ 0`, then `linear_combination`/`nlinarith` on explicit coefficients, looks feasible. The certificate may need `disc^k` with `k > 1`; that is harmless, since `disc ≠ 0`.

**MINOR 3 (shared infrastructure).** D2, D4 and D5 all need the same bridge: for `Cⁿ` functions, `dd Ψ k v w = iteratedFDeriv ℝ 2 Ψ k ![w, v]` and `ddd Ψ k u v w = iteratedFDeriv ℝ 3 Ψ k ![w, v, u]`, plus symmetry. It should be one shared lemma file written before the parts. It may already exist in the S3 proof (`OscInt/StationaryPhase/`), which I was not allowed to read.

**NIT 1 (D7).** The docstring "e.g. a product of two even one-dimensional bumps nonincreasing in `|x|`" suggests monotonicity is needed. It is not: any bump with `rIn = 1`, `rOut = 2` satisfies `χ ((2 : ℝ) • z) ≤ χ z`.

**NIT 2 (unused hypotheses).** `Continuous A` is unused in D8, and `δ ≤ 1` is unused in D9. Both are harmless.

**NIT 3 (D3 docstring).** The docstring says "the Hessian of the cubic is nonzero". The statement `0 < hessNorm (cubicPoly q) z` says exactly that, but neither the docstring nor `proof-S4.md` mentions that `vᵢ ≠ 0` is not stated separately and is not needed (see D4).

The assembly's use of the parts matches their statements. It applies D5 with `Λ = ℝ`, `σ₀ = 0`, applies D2 over `ℝ` and then restricts to `Icc 0 ε₀` (which is compact). The remark in `proof-S4.md` that only `disc ≠ 0` is used is consistent with D3 as stated in Lean.
